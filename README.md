# نسقو برو ERP

تطبيق عربي لإدارة الحسابات والفواتير والأصناف والمخازن والبيانات الإدارية. يحتوي هذا المستودع على واجهة React، وخادم SQLite للويب، وتطبيق Android الذي يحفظ البيانات في SQLite على الجهاز.

## البنية الحالية

- `src/`: واجهة React وTypeScript، النماذج والتقارير والاستيراد والتصدير.
- `server.ts` و`server/`: API الويب، التحقق والصلاحيات والمعاملات وقاعدة SQLite.
- `flutter_app/`: غلاف Flutter، SQLite المحلية، النسخ الاحتياطي والأوامر الأصلية.
- `src/hybrid/` و`flutter_app/lib/hybrid/`: اتصال الواجهة بالأوامر الأصلية مع التحقق من الرسائل ومنع تكرار العمليات.
- `tests/` و`flutter_app/test/`: اختبارات تستخدم بيانات مصطنعة وقواعد منفصلة.
- `.github/workflows/`: فحوص الدمج وبناء حزم Android وحزمة الخادم.

في Android تُحمّل واجهة React من ملفات مضمّنة، وتنفّذ العمليات عبر الجسر في SQLite المحلية. في الويب تتصل الواجهة بـAPI الخادم. ملفات IndexedDB وطبقات التوافق الموجودة ليست قاعدة التشغيل المالية الأساسية لهذين المسارين.

## تشغيل نسخة تطوير للويب

المتطلبات: Node.js 24 وnpm.

```sh
npm ci
npm run check:runtime
npm run dev
```

استخدم نسخة بيانات تطوير منفصلة عبر `NASQO_SQLITE_PATH`. إعداد خادم متاح عن بعد يتطلب مصادقة وتخزين SQLite دائمًا؛ راجع `Dockerfile.deploy` واختبارات `tests/sqlite-local-production.test.mjs` قبل النشر.

## Android

راجع [دليل Android](flutter_app/README.md). الحزم الموقعة المتاحة موجودة في [GitHub Releases](https://github.com/helalalfqih-sketch/NASQO-PRO-ERP/releases). ملف APK للتثبيت، وAAB للرفع إلى Google Play Console. وجود إصدار هنا لا يعني طرحه على Google Play.

## التحقق وحدود النطاق

```sh
npm run lint
npx tsc -p tsconfig.server.json --noEmit
npm run build
npx tsx --test tests/erp-crud.test.ts tests/erp-input.test.ts
```

[تقرير CRUD](docs/verification/full-crud.md) يوضح العمليات المنفذة والاختبارات وحدودها. إنشاء السجلات وقراءتها وتعديلها وحذفها يتم عبر الخدمات وقاعدة البيانات مع حماية المراجع والتاريخ المالي. المستندات المرحّلة تستخدم إجراءات العكس والإلغاء المخصصة.

بعض عمليات الترحيل الإدارية المتقدمة على Android ما زالت تخضع لقيود قدرات المسار الأصلي؛ الفواتير والسندات الأصلية هي مسار الترحيل المالي المتاح. نجاح CRUD لا يعني اعتماد كل تكامل خارجي أو جاهزية كل سيناريو للإنتاج.

لا تُضف قواعد البيانات أو النسخ الاحتياطية الخاصة أو مفاتيح التوقيع إلى المستودع. الاختبارات الآلية لا تستخدم بيانات الإنتاج.
