Built

تم استكمال تطبيق البنية المحلية أولًا (Local-First Architecture) وتدقيق السلامة المحاسبية والمخزنية في نسقو برو ERP دون المساس بتكاملات Firebase السحابية أو Google Drive OAuth القائمة.
1. تحليل البيئة وتشخيص الحالة الفعلية

    إطار التشغيل الفعلي للويب: React + TypeScript + Vite (src/Prototype.tsx وطبقة الخدمات والمستودع)، بينما مجلد flutter_app/ يمثل حزمة تصدير Dart/SQLite مساندة.

    مكامن الخلل التي تم إصلاحها أثناء التدقيق:

        إلغاء الحقن التلقائي للبيانات المالية الوهمية عند التهيئة النظيفة أو إعادة الضبط؛ يبدأ النظام بهيكل حسابات نظيف (Accounts = 0 من العمليات المالية، Ledger = 0)، مع الترقية غير التدميرية لقاعدة IndexedDB من الإصدار v1 إلى v2.

        إرجاء فحص اتصال Firestore الخادمي (testConnection) في وضع العمل المحلي/غير المسجل لتفادي أخطاء الشبكة في وحدة التحكم عند العمل دون إنترنت.

        مزامنة المستودع الافتراضي داخل نوافذ إضافة الصنف والفواتير فور تحميل بيانات warehouses من IndexedDB لمنع بقاء قيمة المستودع فارغة في النماذج المركّبة مسبقًا.

        إصلاح نطاق مخازن معاملات IndexedDB (runTransaction scope) بحيث تتضمن جميع دوال الترقيم المتسلسل مخازن ledger وjournal_entries وinvoices معًا.

        ترقية دالة ميزان المراجعة (computeTrialBalance) لدعم قيود الأستاذ العام المزدوجة المرحلة (JournalEntryRecord بسطري مدين/دائن متساويين) مع الإبقاء على التوافق مع الاستدعاءات الثنائية السابقة.

2. البنية والطبقات المنفذة (UI → Services → Repository → Local DB)

    طبقة التخزين الدائمة (IndexedDB — nasqo_pro_erp_db, Schema v2):

        17 مخزنًا منظمًا بالفهارس والمفاتيح المرجعية: workspaces, branches, accounts, ledger, journal_entries, journal_lines, invoices, invoice_lines, warehouses, inventory, stock_movements, currencies, erp_modules, settings, audit_logs, idempotency_keys, backups.

        دعم العمل الكامل دون اتصال ودون اشتراط Firebase Authentication مع الاحتفاظ بالبيانات بعد إعادة التحميل.

    طبقة الخدمات المعاملاتية (ErpTransactionService) والمستودع (LocalRepository):

        قفل تسلسلي لكل مساحة عمل (withWorkspaceLock) لمنع تضارب المعاملات المتزامنة وفقدان تحديثات المخزون.

        تمنع مفاتيح عدم التكرار (idempotencyKey) وحواجز الضغط المزدوج في الواجهات تسجيل القيود أو الفواتير مرتين.

        التراجع الكامل (Atomic Rollback) في حال فشل أي خطوة، وعدم عرض رسالة نجاح إلا بعد تأكيد الحفظ الفعلي في قاعدة البيانات.

3. السلامة المحاسبية والمخزنية والتقارير

    القيود المزدوجة والاستيراد والمخزون:

        رفض أي قيد غير متوازن (totalDebit ≠ totalCredit) أو مرجع حساب غير موجود في دليل الحسابات.

        تقييد تعديل المبالغ والاتجاه في القيود المرحلة مع توفير «عكس القيد» (reverseEntryTx) لإصدار قيد عكسي متوازن وتوثيقه في audit_logs.

        ربط الفواتير والمرتجعات وأوامر الشراء والتصنيع بتحديث المخزون، متوسط التكلفة المرجح، سجل stock_movements، ومنع السحب على المكشوف (الرصيد السالب) عندما لا يسمح الإعداد بذلك.

    الاستيراد والتصدير والطباعة (CSV / PDF / Backup v3):

        محلل CSV يدعم العربية وRFC-4180 وفحص الأعمدة وكشف التكرار ومعاينة الصفوف قبل الاعتماد الذري (CsvImportModal).

        توليد ملخصات PDF القابلة للطباعة والتحميل (A4 و80mm حراري) بالاعتماد المباشر على سجلات قاعدة البيانات المحلية (exportPdf.ts).

        نسخ احتياطي v3 بتحقق سلامة SHA-256 مع دعم التشفير الاختياري (AES-256-GCM + PBKDF2) ومعاينة/تحقق الاستعادة (BackupRestorePreviewModal) التي ترفض الملفات المعدلة أو كلمات المرور الخاطئة وتتأكد من توازن ميزان المراجعة وسلامة المراجع بعد الاستعادة.
