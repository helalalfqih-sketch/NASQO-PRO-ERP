# إعداد Bitrise — التحقق المحلي

أضيف إعداد `primary` لبناء React محليًا ودمجه في Flutter، ثم تشغيل الفحوص وإعداد APK تجريبي خاص. يبدأ يدويًا، ولا ينشر إصدار إنتاج أو صفحة تثبيت عامة أو رسائل بريد. لم يتغير كود التطبيق أو الحزمة أو توقيع الإنتاج.

مصدر العمل: `06b4a3e1bafe37ec8aa3f01b4edbcde6300ff6e7` على الفرع الحالي بعد 1.0.141. التعديلات في checkout مستقل `/workspace/NASQO-bitrise-setup` وفرع `agent/bitrise-android-ci`. بقي checkout العمل السابق وتعديلاته المحلية، وفرع النشر `dev/offline-first-android-phase2`، دون تعديل.

فشل `npm ci` قبل العمل لأن lockfile لم يتضمن اعتماديات موجودة أصلًا في package.json. سُجل الخطأ في `baseline-npm-ci.log`، وأُصلح في commit منفصل `7942f93`؛ أُضيفت 86 مدخلة اعتماد ولم يتغير إصدار أي حزمة موجودة في lockfile الأصلي. لا يعني ذلك فشل APK المنشور؛ workflow السابق يستخدم npm install.

نجح محليًا:

- فحص `bitrise.yml` بالأداة الرسمية Bitrise CLI 3.4.1، مع التحقق من SHA256 للأداة قبل تشغيلها. هذا فحص schema دون حساب Bitrise.
- npm ci بعد مزامنة lockfile، وفحص 28 ملف runtime محمي، وفحص منع ملفات النسخ الاحتياطية العامة.
- بناء 63 ملف React offline والتحقق من بصماتها بعد دمجها في Flutter.
- 44 اختبار JavaScript، وتوليد هيكل Android الحالي والهوية العربية.
- تحليل Flutter باستخدام `--no-fatal-infos`؛ بقيت ملاحظات info الموجودة في المصدر دون إخفائها أو تغيير قواعد الفحص.
- 94 اختبار Flutter اصطناعيًا، وفق سكربت المشروع المعتمد واستثناءاته الموثقة؛ لا قراءة لنسخة احتياطية خاصة أو بيانات هاتف.

الأوامر نُفذت من السكربت الجديد نفسه للمراحل web/prepare/test. إصدارات التحقق المحلي: Node 24.22.3 وFlutter 3.29.3. إعداد Bitrise يحدد Node 24.12.0 وFlutter 3.29.3 وJava 17؛ لا ندعي تطابق بيئة المضيف كاملًا مع Bitrise.

لم ينفذ: تسجيل مشروع Bitrise أو تشغيل بناء على خوادمه، بناء APK جديد في هذه الدفعة، أو اختبار واجهة Android. مرحلة APK مضافة إلى workflow وتفحص الهوية والعربية وdebug قبل حفظ الناتج، لكن تنفيذها الفعلي ينتظر أول بناء متصل. لم يوضع رمز وصول في الملفات أو السجلات.

المانع الخارجي: لا تعرض الجلسة أدوات Bitrise ولا تعمل أداة التحكم بالمتصفح. `bitrise auth status` يؤكد عدم وجود رمز وصول، كما أن إعداد البيئة لا يحتوي أي أسرار خدمة. يمكن إكمال الربط عبر CLI الرسمي بعد توفير `BITRISE_TOKEN` بأمان في إعداد أسرار البيئة. الدخول في تبويب المستخدم لا يمنح CLI صلاحية الحساب.
