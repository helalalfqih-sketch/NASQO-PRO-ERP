# إصلاح ربط Google Drive وكاميرا QR بعد 1.0.121

المستودع `helalalfqih-sketch/NASQO-PRO-ERP`، ونسخة العمل المعزولة `NASQO-drive-fix`. نقطة البداية هي إصدار Android `1.0.121` عند SHA `b1682a212a8bb86d5748e604556c779f0f230138`. هذا التقرير يخص إصلاحًا محليًا لاحقًا لهذا الإصدار؛ لا يعني أن APK المنشور 1.0.121 يحتوي التغييرات التالية.

## ما ثبت وما لم يثبت

|---|---|---|
| فشل ربط Drive برسالة عامة | [إعادة تمرير أخطاء اصطناعية مختلفة](../deliverables/drive-camera-fix/logs/baseline-error-reproduction.log) أعادت نص «تعذر ربط Google Drive. تحقق من نافذة التفويض وإعداد OAuth…». كان الجانب الأصلي يختزل أخطاء Firebase/Platform إلى `SERVICE_UNAVAILABLE`، ويخلط رفض صلاحية Drive بإلغاء اختيار الحساب، ولا يميز أسباب HTTP 403 | فقدان التشخيص مؤكد. سبب فشل حساب المستخدم أو إعداد Google Cloud/Firebase الفعلي **غير مؤكد**؛ لا تثبت الرسالة القديمة وحدها خطأ عميل OAuth أو الشهادة أو تعطيل API |

## التغيير

تملك `NativeGoogleAccountSession` الآن عميل Google واحدًا فعالًا وتنفذ عملياته بالتتابع. زر ربط Drive الصريح يهيئ العميل بـ `email` و`drive.file` قبل طلب الرمز، بينما يظل تسجيل الهوية وحده بـ `email`. تنشئ كل مصادقة صريحة غلافًا جديدًا، بما فيها إعادة الربط في الوضع نفسه، لاستخدام ID token المعاد في نتيجة تسجيل الدخول الحالي بدل قيمة قديمة في غلاف Dart؛ لا يُعاد استخدام حساب أو عميل متقاعد. تجديد ترويسة Drive يحتفظ بالمالك الحالي دون تسجيل دخول تلقائي. تُسلسل قراءة الرمز والخروج، وتُفحص مطابقة هوية Firebase للحساب قبل استعمال Drive. يثبت اختبار الرجوع أن المسار القديم يطلب رمز `email` فقط رغم الموافقة، وأن المسار الجديد يطلب الصلاحية المطلوبة فعلًا. راجع [الدليل من إصدار إضافة Google المثبت](../deliverables/drive-camera-fix/logs/google-scope-source-evidence.txt).

يمرر ربط Drive الآن رموزًا محددة ورسائل عربية ثابتة من الخدمة الأصلية إلى الواجهة. تميّز الرسائل الإلغاء، نقص الصلاحية، اختلاف الحساب، الشبكة، انتهاء الجلسة، إعداد المزود، تعطيل Drive API وحدود الطلبات. لا يعرض المصنف نص استثناء SDK أو جسم استجابة Google الخام. يُصنَّف تعطيل API فقط عند سبب معروف مثل `accessNotConfigured` أو `SERVICE_DISABLED`؛ لا يُعامل كل 403 على أنه API معطلة.

الضغط السريع المتكرر على الربط يشارك طلب اختيار حساب واحدًا. الإلغاء أو الرد غير المكتمل لا يصنع حالة «متصل»، ويمكن إعادة المحاولة صراحةً. انتهاء الجلسة أو اختلاف الحساب أو رفض الصلاحية يزيل علامة اتصال Drive ولا يفتح تفويضًا تلقائيًا. رقم مراجعة حالة الاتصال يمنع رد status أو connect المتأخر من إحياء اتصال فُصل لاحقًا. تعرض قراءة الحالة الأولى كذلك رسالة مصنفة بدل نص استثناء خام. تبقى الصلاحية المطلوبة لملفات Drive هي `drive.file`؛ لم تتغير إعدادات مشروع Google أو عميل OAuth أو الحزمة أو شهادة التوقيع.

| الرمز/الحالة | الإجراء الذي توضحه الواجهة |
|---|---|
| `GOOGLE_CONFIG_MISSING` / `GOOGLE_PROVIDER_CONFIG` | مراجعة إعداد النسخة ومزود Google وعميل OAuth والشهادة؛ هذا توجيه تشخيصي لا إثبات لسبب بلاغ المستخدم |
| `GOOGLE_AUTH_CANCELLED` | إلغاء اختيار الحساب؛ إعادة الربط عند الرغبة |
| `GOOGLE_SCOPE_DENIED` / `GOOGLE_ACCOUNT_MISMATCH` | الموافقة على ملفات التطبيق أو اختيار الحساب نفسه |
| `GOOGLE_NETWORK_ERROR` / `GOOGLE_TIMEOUT` | فحص الاتصال أو إنهاء شاشة الاختيار ثم إعادة المحاولة |
| `GOOGLE_AUTH_EXPIRED` | إعادة ربط الحساب |
| `DRIVE_API_DISABLED` / `DRIVE_PERMISSION_DENIED` / `DRIVE_RATE_LIMITED` | تفعيل API عند إثبات السبب، أو مراجعة الصلاحية، أو الانتظار بحسب الرمز |
| فشل غير مصنف | رسالة ثابتة ورمز عام، دون ادعاء نجاح الربط أو كشف تفاصيل المزود |

يضيف إعداد Android إذن CAMERA وميزات كاميرا اختيارية، دون فرض كاميرا خلفية أو تركيز تلقائي، ودون إذن ميكروفون أو تخزين. يوافق `WebChromeClient` على التقاط الفيديو وحده من صفحة التطبيق المحلية الموثوقة، بعد قرار إذن Android. تُرفض الموارد أو الأصول الأخرى. يرتبط الرد بطلب الإذن نفسه، وتُلغى الطلبات عند الإغلاق أو توقف الحاوية أو مغادرة الصفحة.

في ماسح QR يبقى عنصر الفيديو مركبًا قبل وصول stream، ولا يبدأ طلب الكاميرا إلا بضغط المستخدم. يُمنع طلب ثانٍ أثناء انتظار الإذن. الإيقاف والإغلاق وإزالة المكوّن وإخفاء الصفحة/إشعار الحاوية يحررون جميع tracks؛ يُحرَّر كذلك stream المتأخر بعد الإلغاء. العودة للواجهة لا تعيد تشغيل الكاميرا تلقائيًا. تختلف رسالة رفض الإذن عن غياب كاميرا أو انشغالها، مع إبقاء رفع صورة QR والإدخال اليدوي بديلين. قراءة الرمز وحدها لا تحفظ صنفًا أو تغير المخزون.

## ما يلزم للتحقق على Android

لم يُجرَ خلال هذا الإصلاح اختبار هاتف/محاكي، ولا تجميع كامل لتعديلات Kotlin، ولا تسجيل دخول Google أو رفع نسخة حقيقية. نجاح بناء APK للإصدار الأساسي 1.0.121 في CI سابقًا لا يثبت بناء هذا الإصلاح أو نجاح سلوكه على الهاتف.

يحتاج قبول الإصلاح إلى نسخة اختبار موقعة بالإعداد المعتمد، ثم فحص إذن الكاميرا لأول مرة، الرفض وإعادة الطلب، الرفض الدائم والإذن من إعدادات النظام، منح متأخر بعد الإغلاق، Home ثم العودة، وإغلاق الماسح مع مراقبة توقف الكاميرا. يلزم كذلك قراءة QR اصطناعي بالكاميرا الفعلية والتأكد أن الاستعلام وحده لا يكتب مخزونًا.

أما Drive فيلزم اختيار حساب اختبار وإلغاء الاختيار وإعادة الربط، رفض/منح صلاحية ملفات التطبيق، ضغط الربط السريع، انقطاع الشبكة، ثم التحقق من ملف اصطناعي بعد رفعه وتنزيله صراحةً. إذا ظهر رمز إعداد المزود أو API تُراجع إعدادات المشروع المعتمد والحزمة وشهادة توقيع النسخة الفعلية قبل الادعاء بأن الربط أُصلح على الحساب. لا تطلب هذه الخطة مسح بيانات التطبيق أو استبدال قاعدة العمل.

هذه أدلة مرحلة التحقق المحلي قبل بناء إصدار الإصلاح ونشره؛ يلزم إرفاق نتيجة CI وبيانات APK بصورة مستقلة عند إصداره. لم تتغير إعدادات حساب Google أو بيانات الهاتف/الإنتاج أثناء هذا التحقق.

عُزلت حالات مشغّل اختبار الرجوع في سياق متصفح مستقل لكل حالة؛ لأن مسح التخزين ثم إعادة تحميل صفحة سابقة قد يعيد حفظ مسودتها عند pagehide. بقيت اختبارات إعادة التحميل داخل الحالة نفسها كما هي؛ لم تتغير آلية حفظ التطبيق لإرضاء الاختبار. أزيلت مسافات نهايات السطور من نسخ السجلات المرفقة.
