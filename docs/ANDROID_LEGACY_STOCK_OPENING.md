# Stock opening after legacy migration (SQLite schema 9)

Open the native inventory icon after activating a legacy SQLite backup. Search the original product, select a warehouse, enter its physically counted whole base-unit quantity and independently verified total cost in base currency. Select the non-cash inventory asset and corresponding opening/adjustment account, date, and count/evaluation reference. The operator must confirm that the same valuation is not already recognized in the accounts. There is no automatic opening valuation from historical sales or catalog prices.

Each source product/warehouse pair can be approved once. The existing catalog identity is used in its originally assigned warehouse; a stable location-specific identity is created for other warehouses, sharing the original catalog units and metadata. Positive quantity needs positive total valuation and posts a balanced opening journal and stock movement. A confirmed zero quantity/zero cost can be opened for later purchases without a zero-value journal. Unapproved source cards remain blocked. Subsequent invoices and returns must use the approved inventory account, warehouse and date. The existing WAC engine maintains value. The opening audit, source link and original SQLite archive are included in native backups. Schema 7 and 8 native backups remain readable. Imported workspaces remain local-only.

This workflow is manual per product/warehouse; it is not a batch count importer or a reconstruction of historical stock transfers, cost of goods, or prior accounting balances. Fractional current base units, free positive opening quantities, mixed currencies, and corrections to already-approved opening counts require additional domain workflows. Historical fractional invoice lines are preserved. The operator must reconcile inventory and the offset with the accounting register before confirming. No real backup data is committed. Physical-device acceptance is still required.
