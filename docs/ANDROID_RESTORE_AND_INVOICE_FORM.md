# Native restore and invoice form separation

React System Settings / Restore from file and the full SQLite import button now call the same dedicated restoreLocalBackup action. Only the local workspace identifier crosses the bridge; Android opens the system file picker, copies to app-private cache, and Dart inspects and restores the selected bytes. The working database is getDatabasesPath()/nasqo_pro_erp.db. Legacy activation populates accounts, ledger and inventory catalog and retains original invoice lines and source bytes. Populated databases still require an independently verified safety export and explicit replacement. Review-only remains a separate choice; no data is sent to the server.

Invoice forms no longer require selecting revenue, inventory, COGS and tax accounts on each invoice. The optional tax controls are collapsed. System Settings / Database / Automatic posting accounts opens a native configuration screen. The user selects existing noncash accounts per currency once. Dart resolves the accounts at posting time; an approved inventory opening takes precedence over the default inventory account. No accounts are fabricated, no legacy classifications are modified, and unknown or inconsistent mappings fail closed. Native backup exports retain the settings; a new legacy restore clears previous role IDs. Existing unapproved imported stock is still blocked until reconciliation. Free credit invoices and balanced stock cash/credit invoices keep the existing engine rules; cash free invoices and editing posted records are not enabled by this change.

Synthetic integration tests exercise invoice payloads without counterpart fields after legacy activation, settings persistence through native export/restore and reset on a different legacy restore. Bridge tests verify native restore accepts no file contents from JavaScript. Real-device acceptance is still required.
