# Android document output parity

The original invoice and dashboard PDF generators, CSV export actions and PNG summary export use a bounded native handoff when running in the hybrid Android build. React transmits generated bytes in sequential 20 KiB chunks. Dart restricts size (16 MiB), filename, MIME type and offsets, verifies the PDF/PNG signature, and cleans its private temporary folder. Kotlin uses the Android document picker and reads the saved file back to verify its digest. Cancellation is not reported as a successful save.

Sharing uses a non-exported FileProvider restricted to the shared document cache subtree and Android's user-controlled chooser. Text sharing and targeted WhatsApp compose requests open the selected app or the chooser; the application never sends the message automatically. Native print opens the Android print preview of the current WebView page, not an invisible or reconstructed all-currency report. The user can choose Save as PDF or a printer; a preview request does not prove printing or saving finished.

PDF invoice summaries now prefer actual source invoice lines over descriptions parsed from the display string. Long-document pagination/print CSS, device-specific printer compatibility, precise all-currency output, and actual on-device share/save acceptance still require testing. Existing summary image exports remain summaries, not full multi-page reports. No accounting data or remote deployment is changed.
