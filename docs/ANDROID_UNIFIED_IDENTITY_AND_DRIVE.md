# Android unified React shell and Google connection

Android launches the packaged React interface for both debug and release. The duplicate native app bar, ordinary-state banner and secondary Flutter dashboard selector are no longer presented. The existing React settings contain Google identity and imported-data controls. Native utility dialogs, reconciliation screens, file pickers and the official Google account chooser remain native where needed. A short React warning is visible only while reviewing an isolated backup.

Google identity uses the existing Firebase configuration and native Google Sign-In. The local workspace ID stays unchanged. Drive consent is separate and uses the limited drive.file scope; the native layer verifies the selected account against Firebase and Drive about. The WebView receives account information and a non-secret session marker only. No automatic enrollment, upload, or cloud synchronization occurs. Drive connection is in memory and can be reauthorized after app restart. Signing out leaves SQLite intact.

Drive files are accessed through a fixed Google API origin, not arbitrary URL or filesystem bridge requests. The native Drive manager supports folder listing, folder creation, user-confirmed local file upload, download through Android's file picker, trash and explicit backup/overwrite/restore. Full database backup comes from the native SQLite exporter, not a reduced React snapshot. Restore uses the same inspection, safety copy and explicit replacement rules as local restore. Upload is size-limited, checked against the returned size and checksum. Permanent deletion is deliberately unavailable on Android. Google-native Docs/Sheets exports and resume-after-interruption are not implemented. The Drive API must be enabled in the associated Google Cloud project, and the registered Android signing certificate and OAuth consent configuration must be correct.

Tests use synthetic requests and disconnected native state. Actual Firebase and Drive authorization, upload/download and layout on an Android phone require device acceptance. No cloud resource settings or private backups were changed by these commits.
